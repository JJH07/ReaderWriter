# 검토 후 수정 내역

## 호환성 기준

기준 원본은 `a2dbeb73c1d2b5e7a58cf536b27dd4c40497d3e0`입니다. 사용자 기능의 추가·제거 없이 원본 계약을 유지하고, 빌드와 실행에 필요한 저장소 파일은 원래 세 개로 제한합니다.

| 항목 | 유지하는 내용 |
| --- | --- |
| 데몬 | 기본 백그라운드 실행, `-l -t -n -p -id` |
| 클라이언트 | `-r -w -rw`, `-t -s -d`, 기존 인자 위치 |
| 확인 입력 | `yes`일 때 편집, 그 외 취소 |
| 편집기 | `/usr/bin/vim` |
| 대기 | 기본 무기한, 원래 대기 문구 |
| 통신 | `./tmp/fifo`, 원문 파일명, `SIGUSR1/SIGUSR2` |
| 출력 | 원래 표제·문구·크기 형식, 일반 `diff` |
| 변경 판정 | 원래 초 단위 `st_mtime` 비교 |
| 로그 | 원래 파일 경로·사용자 정보·초 단위 복사본 이름 |
| 소스 | `ssu_ofm.c`, `ssu_vim.c`, `Makefile`만 필요 |

앞선 정비에서 도입했던 Unix 소켓, 공통 소스·헤더, 전경 실행 옵션, 소켓 경로 옵션, 대기 제한 옵션, `EDITOR` 선택과 변경된 diff 형식은 원본 계약에 맞게 되돌렸습니다.

## 내부 버그 수정

| 문제 | 수정 |
| --- | --- |
| 옵션 값 누락·버퍼 범위 초과 | 인자 개수, 숫자 범위, 경로 길이 확인 |
| FIFO 생성 오류 분기·디렉터리 접근 문제 | 반환값과 실제 파일 유형 확인, 디렉터리에 탐색 권한 부여 |
| 시그널 핸들러에서 비동기 안전하지 않은 함수 사용 | 신호를 동기적으로 수신한 뒤 로그·큐 처리 |
| 동시 요청의 파일명·PID 혼선, 요청 유실 | 기존 FIFO 쓰기·통지 직렬화, 큐 용량에 따른 대기 |
| 죽은 대기 프로세스가 큐를 막음 | 종료·좀비 프로세스를 확인하고 다음 요청 진행 |
| 취소 시 `tempXXXXXX`라는 사용자 파일 삭제 | 실제 생성한 임시 파일만 삭제 |
| 잘못된 시각 출력 | 별도 `struct tm` 값으로 수정 시각·현재 시각 계산 |
| 복사·자식 실행 실패 후 잘못된 진행 | 부분 입출력, 자식 종료 상태, 디스크립터 수명 확인 |

정상 입력의 기능과 출력 계약을 기준으로 검증합니다. 잘못된 입력에서 발생하던 충돌·메모리 손상·파일 오삭제는 유지하지 않습니다. 모든 환경과 모든 타이밍에서 원본 바이너리와 바이트 단위로 같다는 보장은 하지 않습니다. 특히 원본의 버퍼링 오류와 시각 계산 오류는 수정 대상입니다.

검사 항목과 실행 방법은 [TESTING.md](TESTING.md)에 기록합니다.

## 후속 리뷰: 1번 항목만 수정

요청자가 FIFO 쓰기와 `SIGUSR1` 전송 직후 종료하면, 남은 데이터만 지우고 시그널은 남겨두던 경로가 있었습니다. 다음 요청자의 파일명을 이전 요청자의 PID와 연결하여 버릴 수 있었습니다. FIFO 잠금을 보유한 상태에서 남은 `SIGUSR1`과 데이터를 모두 소비한 뒤 다음 송신자에게 잠금을 넘기도록 수정했습니다. 완료 통지인 `SIGUSR2`는 이 정리에서 소비하지 않습니다.

제품 코드 변경은 `ssu_ofm.c`의 해당 정리 분기에 한정합니다. `ssu_vim.c`, `Makefile`, 옵션, 출력 문자열, FIFO 데이터 형식, 시그널 종류, 정상 대기 정책은 변경하지 않습니다. 빌드·실행 필수 파일은 원래 세 개입니다.

수정 전 [재현 실행](https://github.com/JJH07/ReaderWriter/actions/runs/42432478897)에서는 GCC·Clang·Sanitizer 모두 새 회귀 테스트의 후속 편집 요청이 시간 초과했고, 기존 21개 테스트는 통과했습니다. 테스트는 실제 데몬 소스를 임시로 컴파일하면서 FIFO 정리 전후에만 정지 지점을 넣어 같은 실행 순서를 강제합니다. 테스트용 코드와 파일은 제품의 빌드·실행 의존성이 아닙니다.

다음 두 리뷰 항목은 사용자 지시를 기다리며 이번 수정에 포함하지 않습니다: 큐가 가득 찼을 때 다른 파일명 요청의 거부 지연, 리다이렉션 시 원본과 다른 출력 순서. 따라서 이번 검증을 원본 전체 입출력의 완전 동일성으로 해석하지 않습니다.

수정 후 [검증 실행](https://github.com/JJH07/ReaderWriter/actions/runs/42432895043)에서 새 회귀 테스트와 기존 21개 테스트가 세 구성 모두 통과했습니다. 실행 필수 세 파일만 복사한 빌드 검사도 통과했습니다. 이번 수정으로 정상 경로의 옵션·출력·파일 형식에 새로운 차이는 확인되지 않았으며, 수정 대상은 종료된 송신자 때문에 후속 요청이 영구 대기하던 오류입니다.
